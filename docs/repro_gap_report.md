# MSA Reproduction Gap Report

## Scope and method

This report audits the published repository code paths to assess reproducibility for:
- inference execution,
- model loading and checkpoint assumptions,
- training readiness (from scratch and continued pretraining).

I traced runtime entrypoints, model initialization, memory pipeline code, and utility modules under `src/` and `scripts/`.

---

## 1) Inference entrypoints

### Primary CLI entrypoint
- `scripts/run_benchmarks.sh` is the top-level runner used in README/quick start and repeatedly invokes `python -u src/app/benchmark.py ...` with benchmark-specific arguments and model path (`ckpt/MSA-4B`).
- This is the practical production entrypoint documented for users.

### Python benchmark entrypoint
- `src/app/benchmark.py` `__main__` parses CLI args, resolves benchmark data through `BenchMarks`, and calls `msa_benchmark(args, data)`.
- `msa_benchmark` constructs `ModelConfig`, `GenerateConfig`, and `MemoryConfig`, then instantiates `MSAEngine` and calls `engine.generate(...)` in a loop.

### Engine-level entrypoint
- `MSAEngine.initialize()` loads tokenizer, memory file, starts worker processes, then serves generation requests.
- The engine is the actual runtime orchestrator for:
  - memory prefill stage 1,
  - retrieval/routing,
  - sparse generation.

### Secondary evaluation entrypoint (not inference core)
- `scripts/calculate_llm_score.sh` runs `src/evaluation/llm_judge.py` to score already-generated outputs via OpenRouter API.
- This is post-hoc evaluation, not model inference.

**Inference reproducibility status**: usable for benchmark inference with released checkpoints, but tightly coupled to specific benchmark data format and runtime hardware assumptions.

## 2) Model loading path

### Model class and config
- Model class: `src/msa/model.py::MSAForCausalLM` (inherits `Qwen3PreTrainedModel` + custom generation mixin).
- Config class: `src/msa/configuration_msa.py::MSAConfig`, extending `Qwen3Config` and wrapping `msa_config` as DotDict.

### Where model is loaded
- Prefill worker loads model via:
  - `MSAForCausalLM.from_pretrained(model_path, use_cache=True, attn_implementation="flash_attention_2", torch_dtype="bfloat16", device_map=self.device)`.
- Memory worker generation path loads similarly with `torch_dtype="auto"`.
- Service/engine separately loads tokenizer from same path.

### Expected model package layout
- Must be a Hugging Face-style model directory accepted by `from_pretrained`.
- `config.json` must include `msa_config`; benchmark code explicitly reads it (`read_config_to_args`) to extract:
  - `doc_top_k`,
  - `pooling_kernel_size`,
  - `router_layer_idx`.

### Conversion path from base model
- `scripts/resave_model.sh` + `src/utils/resave_model.py` converts a base model into an MSA-format checkpoint by:
  - building `msa_config` from env vars,
  - loading base config with `MSAConfig.from_pretrained(...)`,
  - loading weights with `MSAForCausalLM.from_pretrained(...)`,
  - `save_pretrained(...)`.

**Gap**: no documented, tested pipeline that trains and then packages checkpoints end-to-end. Repository only includes conversion + inference loading.

## 3) Checkpoint format assumptions

## 3.1 Model checkpoint assumptions (HF weights)

The code assumes:
1. Hugging Face checkpoint layout (tokenizer + config + weights) compatible with `from_pretrained`.
2. `config.json` contains `msa_config` keys required by runtime attention/routing logic.
3. Base architecture is Qwen3-compatible (`transformers.models.qwen3.*` imports are hard-coded).
4. FlashAttention2 environment is available (`attn_implementation="flash_attention_2"` + explicit import requirement in `memory_sparse_attention.py`).

If any of these are missing, model initialization/inference fails.

## 3.2 Memory-bank cache assumptions (separate from model weights)

MSA runtime additionally uses a serialized memory cache format for fast reuse:
- directory with `stub.json`, `meta.pt`, per-layer tensors (`layer_{i}_k.pt`, `layer_{i}_v.pt`, optional `layer_{i}_rk.pt`), and optional `prefix_cache.pt`.
- deserialization expects those files and specific tensor shapes/fields in `meta.pt`.

These are generated by internal `Memory.serialize()` and loaded by `Memory.deserialize()` when `MEMORY_DATA_PATH` is set.

## 3.3 Input memory corpus assumptions

`_load_memory_file` supports only:
- `.json` (assumed to already be list-like context items), or
- `.pkl` (loaded as iterable of documents).

No schema validation, no canonical dataset builder, and comments indicate JSON handling is placeholder (“need to implement according to actual JSON format”).

## 4) Modules that appear training-related but unused

The repository contains training-oriented utilities, but no active training entrypoint references them.

### Likely unused in current inference-only flow
1. `src/utils/callbacks.py`
   - Defines multiple `TrainerCallback` classes (`ModeltimeCallback`, `SacredCallback`, `ModelEvalCallback`, etc.).
   - Not imported by inference pipeline (`benchmark.py` / `msa_service.py` / `prefill.py`).
2. `src/utils/data_utils.py`
   - Contains dataset packing, sequence parallel split, lmdb utilities, post-processing for training datasets.
   - Not wired into any executable training script in this repo.
   - Contains debug breakpoint (`import pdb; pdb.set_trace()`), indicating incomplete productionization.
3. `src/utils/misc.py`
   - Contains training scheduler patch and grad-clip patch helpers.
   - Not used by current inference path.
4. `src/utils/common.py` (partial)
   - Includes training/finetuning helpers (e.g., tokenizer embedding resize, trainable param reporting) not consumed in benchmark runtime.
5. `src/msa/model.py` training branches
   - Implements multi-loss training logic (`lm_loss`, `aux_loss`, `reconstruction_loss`, `answer_loss`), but there is no repository trainer loop invoking these pathways with required labels.

### Additional inconsistency signal
- `src/utils/data_utils.py` imports `pdb_debug` from `src.utils.common`, but that symbol does not exist in `common.py`.
- This suggests stale or partially migrated training code.

## 5) Missing pieces required to train from scratch or continue pretraining

Below is the concrete reproduction gap list.

## 5.1 Missing executable training pipeline

No script exists for:
- dataset loading/tokenization for pretraining/SFT,
- dataloader construction,
- optimizer/scheduler setup,
- distributed launch (DDP/FSDP/DeepSpeed/Accelerate),
- train/eval loops,
- gradient accumulation/checkpoint cadence,
- resume-from-checkpoint.

Only inference and scoring scripts are provided.

## 5.2 Missing training data specification and preprocessing contracts

Absent artifacts:
- training dataset manifest(s),
- data schemas for required model inputs,
- tokenization/chunking recipes,
- creation of `doc_ids` conventions used by MSA attention.

Critical hidden assumption in attention code:
- `doc_ids > 0` = memory doc tokens,
- `doc_ids == 0` = routing query tokens,
- `doc_ids == -2` = template prefix tokens.

No public builder enforces this convention for training corpora.

## 5.3 Missing supervision construction for auxiliary losses

Model forward expects optional labels/fields for multi-objective training:
- `batch_aux_labels`,
- `batch_reconstruction_labels`,
- `batch_answer_labels`,
- `train_qa_samples`.

No repository code constructs these tensors from raw datasets.

## 5.4 Missing pretraining/continued-pretraining checkpoint recipes

For continuation pretraining reproducibility, missing:
- checkpoint naming/versioning policy,
- save/load of optimizer/scheduler/scaler states,
- exact precision setup (bf16/fp16/tf32/etc.),
- sequence length curriculum implementation (README claims 8k→64k SFT, but no code),
- hyperparameter config files for paper runs.

## 5.5 Missing dependency/runtime contract for training

Inference dependencies are listed, but training runtime contract is incomplete:
- no launcher instructions,
- no expected hardware profile,
- no memory/perf tuning flags,
- no deterministic seed policy for distributed training,
- no validation harness integrated into train loop.

## 5.6 Missing architecture registration/packaging hardening

Potential pitfalls for reproducibility:
- custom config/model registration through `AutoConfig`/`AutoModel` is not explicitly wired in repo; pipeline relies on direct class loading.
- strict dependence on Qwen3 internals in `transformers==4.51.3`; no compatibility matrix beyond that pinned version.

## Proposed implementation order (to close gaps)

Priority is set to produce a minimally reproducible training stack quickly, then harden.

### Phase 1 — Establish a minimal runnable trainer (P0)
1. Add `train.py` (or `src/app/train.py`) with a single-node baseline loop:
   - load `MSAForCausalLM` + tokenizer + config,
   - run LM-only loss first (`labels`) on synthetic/mini dataset,
   - save/resume model checkpoints.
2. Add one documented YAML/JSON config for hyperparameters.
3. Add CLI with deterministic seed and logging.

### Phase 2 — Data contract and builders (P0)
4. Define canonical training sample schema including `input_ids`, `attention_mask`, `position_ids`, `doc_ids`, `labels`.
5. Implement dataset builder that enforces `doc_ids` semantics (`-2/0/>0`) and validates sequence/chunk assumptions.
6. Add unit tests for schema and mask validity.

### Phase 3 — Enable full MSA objectives (P1)
7. Implement label constructors for `batch_aux_labels`, `batch_reconstruction_labels`, `batch_answer_labels`, `train_qa_samples`.
8. Wire these into collator + trainer; expose loss weights via config.
9. Add sanity checks/metrics for aux loss (`recall@k`) during training.

### Phase 4 — Distributed and continued pretraining support (P1)
10. Add distributed launch path (Accelerate/DeepSpeed/FSDP) and tested examples.
11. Save/load full training state (optimizer/scheduler/scaler/global step) for true continuation.
12. Add long-context curriculum scheduler (8k→64k) as an explicit module.

### Phase 5 — Reproducibility hardening (P2)
13. Publish reference training configs matching paper claims.
14. Add e2e smoke test: tiny corpus → 10 steps train → checkpoint resume → inference benchmark.
15. Clean or archive stale utilities (`callbacks.py`, `data_utils.py`, `misc.py`) and remove dead imports/debug breakpoints.
16. Add strict checkpoint validator script (checks `msa_config` keys + model compatibility + flash-attn readiness).

---

## Executive summary

The repository is currently inference-first and checkpoint-consumer oriented. It provides strong infrastructure for memory prefill/routing/generation at inference time, but does **not** provide the executable, documented, and validated components needed to reproduce training from scratch or continue pretraining with paper-level fidelity. The highest-impact missing assets are a real training entrypoint, data/label builders for MSA-specific supervision, and full-state checkpoint resume support.
